## Package bytes

All 71 installed `.pak` files were read without modification.

- Every file starts `PACK`. Header bytes 4–7 and 8–11 decode as little-endian index offset and index size; offset plus size equals file length.
- The index is a nonzero multiple of 256 bytes. All 36,512 rows decode successfully and have zero path padding.
- Bytes 0–247 hold an ASCII path and NUL padding. Bytes 248–251 decode as payload offset; bytes 252–255 decode as payload byte length.
- All 36,512 payload offsets are divisible by 4096. Every payload ends before the index, and ranges do not overlap within each package.
- Spot reads matched the `.dds` (`DDS `), `.png` (PNG signature), and `.ogg` (`OggS`) payload signatures. The sample `.ai` starts with readable text (`Tags: NoFlowDash`).
- Extractor validation on the 39-entry `sprites.pak`: all extracted file SHA-256 values matched hashes computed independently from the original byte ranges; the source package hash matched the manifest. See `VALIDATION.md`.
- The tool can create an out-of-place `.pak` candidate with one same-size replacement. Its no-op round-trip was exercised; a behavior-changing replacement has not been loaded by the game. Different-size assets remain unsupported.
- Same-size writer round-trip: replaced the 96-byte `data/ai/aang.ai` with an identical copy and rebuilt `sprites.pak`; the new package's SHA-256 exactly matched the original. This validates no-op package preservation, not a behavior-changing replacement. See `VALIDATION.md`.
- Path names: 34,607 start with `srcdata`, 1,905 with `data`; suffix counts include `.munged` 32,816, `.sprbin` 363, `.dds` 594, and `.ogg` 1,069.
- A sampled Aang combat frame (`srcdata/munged/frames/sprites~aang~blocking~c.block~frames~block_crouch01.munged`, in `aang.pak`) is not a PNG stream. It contains the source PNG path, image-type value 3, crop/canvas/atlas metadata, an occupancy mask, and compressed image chunks. The same PAK includes `srcdata/munged/scripts/sprites~aang~aang.sprbin`, so palette data is separate from frames.
- The community project [calebrisc/avatar-legends-tools](https://github.com/calebrisc/avatar-legends-tools) documents MUNGED decoding/encoding, `.sprbin` palette work, and PAK rebuilding. The new GUI can call its decoder and packer after the user selects that external tools folder; the scripts are not bundled. Its README claims a modified PAK must replace a shipped PAK to load, and an extra PAK does not override paths. This is external documentation and has not been independently verified here.
- Bounded path scan within those package indexes: 33,507 paths under `srcdata/munged`, 1,072 under `srcdata/levels`, 27 under `srcdata/fonts`, one under `srcdata/localization`, and no path under `srcdata/scripts`. This suggests packaged sprite script sources may be absent; it is not a search of external developer tools or other game directories.

These byte observations and the extraction/hash comparison strongly support the stated index and payload layout. No compression or encryption has been observed at the sampled payload starts; the full payload formats are not all understood.
